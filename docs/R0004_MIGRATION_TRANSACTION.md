# R0004 first-migration transaction — design gate

Status: **DESIGN, NOT DEPLOYABLE** (2026-09-26). The running Beget code is R0003 with the compatible counter-only hotfix on all four handlers. Its public OAuth process uses a separate code root and does **not** implement the R0004 admission flag. No command in this document authorizes changing the live VPS.

## Transaction sequence

| Phase | Durable action and proof | Traffic/state boundary |
|---|---|---|
| Prepare | Verify production-pinned signature, build dependencies in quarantine, promote inert version, check disk and current systemd layout. Back up the four legacy fragments, OAuth drop-in, dedicated proxy units and tunnel unit. | Existing R0003 remains active. No version pointer or state change. |
| Boot guard | Install and verify scoped systemd conditions on the dedicated proxy socket/service and tunnel so an on-disk transaction marker prevents them restarting after a reboot. Record previous unit files and guard state. | With no marker, routes are still live. Guard must not affect other Traefik routes. |
| Close ingress | Durably write the transaction journal and marker, then stop proxy socket/service and tunnel. Confirm no bridge-specific public ingress remains. | R0003 does not understand the new pause flag; stopping ingress is mandatory. |
| Quiesce | Stop OAuth MCP, base MCP and Agent, wait for their exit, check the durable terminal operation ledger, then stop Session Host with `KillMode=process`. | Prior file transfers must have finished or failed with atomic cleanup. Do not replay UNKNOWN operations. |
| Snapshot | Take one private, synced bundle of split config and all active SQLite stores while writers are stopped. Preserve retained transcripts and old code roots. | Failure leaves old units and code intact and restores only already-stopped services. |
| Switch | Persist journal phase, write managed unit overrides for all four app services, daemon-reload, switch the code pointer, and start Session Host → Agent → base MCP → OAuth with the persistent R0004 pause flag present. | No public ingress yet. A local health check must verify each service and data schema. |
| Release | After local health, remove the boot guard marker; start dedicated OAuth proxy and tunnel while R0004 still returns 503 for non-health requests. Check the intended public OAuth route, then clear the R0004 pause only after the complete health proof. | Record exact version, artifact digest, schema, CI run and endpoint evidence. |

The root-owned transaction journal needs an explicit phase, old and new code identities, unit-file hashes, snapshot path, admission-marker state, active-service set and exact release artifact digest. Each phase must be synced **before** the next externally visible mutation. A recovery process must inspect this journal before any ingress unit is allowed to start after a reboot. A stale activation lock or an incomplete journal is a stop condition, never permission to remove the marker automatically.

The scoped boot-guard drop-ins can now be prepared and checked with `scripts/release/ingress-boot-guard.mjs`. They use `ConditionPathExists=!/var/lib/dp-beget-bridge/migration-incomplete` on the proxy socket, proxy service and dedicated tunnel only. The marker is persistent across reboot. This helper **does not install** the drop-ins or create/remove the marker. A journaled installer must verify that the original units were snapshotted, install and `daemon-reload` the guards, check that systemd loaded each condition, and only then write and sync the marker before closing ingress. Guard conditions by themselves do not close an already-running socket or tunnel.

After the future install and `daemon-reload`, `scripts/release/installed-ingress-guard-preflight.mjs` checks that systemd reports each exact root-owned guard as the sole drop-in for its expected unit fragment. A missing reload, another drop-in or altered guard fails the check. This read-only check cannot establish that ingress is already closed: the socket and tunnel must be explicitly stopped and observed inactive after the persistent marker is synced.

The four app services also have `Restart=on-failure` and may be enabled at boot. Closing ingress alone does not keep writers stopped after a reboot. `scripts/release/writer-boot-guard.mjs` stages separate guards for Session Host, Agent, base MCP and OAuth MCP. Its systemd conditions allow ordinary starts when the persistent migration marker is absent, or an explicitly permitted start under that marker using a short-lived file under `/run`. A reboot removes that permit, leaving writers blocked while an incomplete migration marker remains. The isolated installer, loaded-unit verification and candidate activation use these guards; no guard has been installed on Beget. Root-only tests evaluate the conditions with `systemd-analyze` in both marker and permit states.

The CI systemd job also installs two uniquely named, disposable services on its runner with the exact ingress and writer condition contents. It checks real `systemctl start` behavior with no marker, with a persistent marker, and with a temporary writer permit. Marker creation does not stop an already-running service; explicit stops remain necessary. This exercise validates condition behavior on the runner, not the exact seven-unit Beget deployment or a full rollback transaction.

The CI-only rehearsal installs seven disposable units with the exact R0003 migration names on an isolated GitHub runner, refusing any pre-existing unit or work directory. It snapshots their fragments, journals activity, installs seven boot guards, closes dedicated ingress under a persistent marker and quiesces four writers. It snapshots three disposable SQLite stores plus configuration, installs four managed drop-ins and verifies the loaded systemd bindings. The expanded rehearsal activates an inert versioned candidate under the scoped writer permit, rejects a simulated public route before exposure, then stages and replaces old state, removes the candidate pointer, restarts the original units and reopens the fixture ingress. It checks that a candidate change to a disposable SQLite store is absent from the restored database. Fixture-only health, drain, public response and route callbacks replace live network proofs: this test does not exercise the real signed artifact or authorize a Beget migration.

The same disposable seven-unit rehearsal also exercises a scoped `/run` permit after quiescence. It interrupts the inert old-writer startup after the first real systemd service has started, verifies that the permit was removed and the remaining three cannot start unpermitted, then opens another scoped permit and starts only the inactive suffix. All three ingress units remain inactive throughout. This tests partial startup and retry under loaded guards, but does not restore data or execute the journaled `restartLegacyAfterRollback` controller; those full rollback steps still need systemd evidence.

`scripts/release/installed-writer-guard-preflight.mjs` verifies the exact four root-owned guard files and the loaded systemd `DropInPaths`, allowing only the pre-existing OAuth compatibility drop-in and, in a later managed phase, the expected managed binding. The isolated ingress-closure function now requires this proof and an absent transient writer permit **before** writing the persistent marker. The isolated installation step follows below; no guards have been installed on Beget.

`scripts/release/install-migration-boot-guards.mjs` now implements that isolated installation step without a CLI. It requires the exact journal-bound seven-unit backup and original layout (including the OAuth compatibility drop-in), absent marker and permit, and verified staged contents for three ingress plus four writer guards. It records `guarded` intent before writing any new drop-in, syncs all seven files, reloads systemd and verifies both loaded guard sets. If a write or reload fails, the marker remains absent and the journal records the incomplete guarded phase for inspection. It does not automatically remove partial files or close ingress; R0003 can continue under its original active services. No guards have been installed on Beget.

`scripts/release/close-legacy-ingress.mjs` now implements the isolated closure phase without a CLI: it verifies the installed guard and journal-bound unit backup, rechecks legacy service activity, requires a fresh independent exclusive public OAuth route proof **and** the real public R0003 OAuth challenge before writing the persistent marker. It then records `ingress-closed`, stops only the dedicated proxy socket/service and tunnel, confirms inactivity, and rechecks route exclusivity after the stops. A failed initial route or public challenge leaves the marker absent and the journal `guarded`; a failed stop or final proof leaves the marker and journal for recovery. The public challenge alone cannot identify Traefik's upstream service. This helper cannot be used on Beget until a live exclusive route proof and the full migration installer have tested recovery paths.

`scripts/release/quiesce-legacy-writers.mjs` implements the following isolated phase without a CLI: it checks that all ingress units remain inactive, the marker is trusted, all four writer boot guards are loaded and the ephemeral permit is absent. It requires an independent bounded proof that accepted R0003 requests have drained, verifies `KillMode=process`, records quiescence intent, then stops OAuth MCP → base MCP → Agent. It checks the terminal operation ledger before stopping Session Host last. Failures retain the marker and journal. The deployed R0003 health counters enable a bounded drain observation only after a proven ingress closure; the installer still needs a live exclusive-route callback before this phase can run on Beget.

`scripts/release/snapshot-legacy-state.mjs` binds the synced grouped config/SQLite snapshot to the journal only after the backup routine has checked stopped writers before and after copying. It also rechecks the loaded writer guards and absence of the transient permit on both sides of the backup. Recovery compares the bundle-manifest digest to journal format v4. A changed inner file still needs the full restore verifier before it can be used for rollback. Failure leaves ingress closed and the journal in quiescence intent for inspection.

`scripts/release/inspect-beget-legacy-data-bindings.mjs` is a separate root read-only check of the **running R0003** process data sources. It reads only the required directory/mode fields from each process environment without printing secrets, verifies stable service PIDs, compares the Session Host, Agent and OAuth SQLite paths against the three declared sources, and rejects unlisted SQLite files. OAuth's data-directory default is admitted only when the running process working directory points to the observed separate code root and its config source matches the observed SHA-256. The first root run failed on a retained Session Host backup-v0; the next failed on a retained OAuth `auth.sqlite.backup-v1`. After admitting these observed files, the root run at `bb04683` returned `bindings_status=0` for all three running services. This does not stop writers, prove requests drained or authorize a snapshot.

Before creating the grouped snapshot directory, `scripts/release/inspect-state-bundle-space.mjs` checks the destination filesystem with `statfs` and sizes all listed SQLite sources and their existing WAL, SHM and rollback journal sidecars. It confirms writers are stopped before measuring, reserves four copies of those sized bytes, four times the accepted 16 MiB configuration ceiling, and 512 MiB remaining free. A low-space result fails before writing a bundle. A connected Beget `df -B1` reported 6,643,093,504 bytes available on the shared `/dev/vda1` on 2026-09-26. A later root read-only inventory counted three expected SQLite files and their live journals with 6,642,659,328 bytes free; see `docs/R0004_LIVE_INVENTORY.md` for exact sizes and caveats. Candidate preparation separately reserves archive staging, extraction and estimated dependency and npm cache space. Because `/opt` and `/var/lib/dp-beget-bridge` share a volume, the first-migration preparation API can require the **sum** of both budgets before creating a workspace. The CLI has no migration inventory, and no root Beget combined preflight has executed on the actual signed candidate; unit-bound database paths, remaining backup files and npm peak use still require a fresh check.

`scripts/release/stage-managed-unit-overrides.mjs` prepares four root-owned service drop-ins pointing at the versioned `current` link without changing the legacy fragments or OAuth environment file. `scripts/release/installed-managed-unit-preflight.mjs` checks that systemd actually loaded those bindings, rejects any extra drop-in and preserves `KillMode=process` for Session Host. Neither helper installs the files or changes running services. Their installation must be part of the later journaled switch, with the original unit snapshot available for rollback.

`scripts/release/install-managed-overrides.mjs` adds the isolated installation phase without a CLI. It requires a trusted persistent marker, a journal-bound state snapshot, inactive ingress and stopped writers. It compares installed legacy app unit files with their backup, verifies staged overrides, records switch intent, writes and syncs only the four managed drop-ins, reloads systemd, and checks the loaded bindings. Partial failure leaves the marker and journal in place; removing overrides and restoring the old unit view is a separate recovery transaction. The version pointer and services are not switched by this helper.

The managed installation now also requires all four writer guards to be loaded, an absent ephemeral writer permit, and exactly the expected pre-existing drop-ins before it records switch intent. Its loaded-unit preflight accepts the ordered writer guard plus managed binding (and the older OAuth compatibility drop-in) and checks the guard content. Candidate startup under the persistent marker uses the controlled `/run` permit described below.

`scripts/release/writer-start-permit.mjs` now provides that root-only scoped lifecycle: verify the persistent marker, create a private `/run` permit exclusively, perform candidate startup and local health under it, then remove it on both success and failure. The activation phase wraps only its four ordered starts and health check with this permit; the pointer and candidate rollback remain outside. Quiescence, snapshot and ingress release refuse a leftover permit. A reboot removes the `/run` directory and permit, so pending recovery cannot start writers automatically. The guarded installation phase verifies that systemd loaded the conditions before the marker is written; activation verifies their managed view before granting a startup permit.

The version-pointer primitive now syncs the release directory around link creation, rename, restoration and activation-lock removal. If a sync fails after `current` changes, it inspects the actual pointer and restores the old target; if restoration itself fails, it retains the activation lock for recovery. This remains pointer-level safety only: service restart and grouped-state rollback must be orchestrated separately while ingress is closed.

`scripts/release/activate-managed-release.mjs` adds an isolated activation phase without a CLI. It checks the exact candidate commit/digest against the journal, verifies both backups, requires inactive ingress and stopped writers, verifies the managed unit bindings, then creates the persistent R0004 admission pause before switching `current`. It starts Session Host → Agent → base MCP → OAuth and requires all four local health endpoints to report paused, drained state before recording `locally-healthy`. If startup or health fails, the pointer is restored and candidate services are stopped in reverse; marker and pause remain. Candidate startup may change database schemas, so this does not itself restart R0003 or restore live state on failure.

`scripts/release/open-managed-ingress.mjs` is an isolated, root-only final phase without a CLI. It requires the journal at `locally-healthy`, the exact candidate digest and active version pointer, no activation lock, intact unit and state backups, a verified persistent marker and admission pause, loaded dedicated ingress and managed app units, inactive ingress, and locally paused/drained candidate services. Its caller must independently prove that the public OAuth hostname has an exclusive route to the dedicated socket. Only then does it journal possible exposure, remove the marker, start the socket and tunnel, verify a real public non-health request is denied by the R0004 pause, and recheck local health and route exclusivity. It clears the pause only after another health and public check, then records `completed`. An early failure recreates the boot guard before stopping ingress and leaves the journal at `ingress-open` for inspection. A failure while clearing the pause may mean users have already entered; recovery classifies `ingress-open` as possibly exposed and never rewinds state automatically. The public probe now makes a bounded HTTPS request to the fixed public `/mcp` path and requires the R0004 `503 admission_paused` JSON response without a redirect. The exclusive Traefik route proof still has no default implementation, so this helper cannot run against Beget yet.

`scripts/release/migration-journal.mjs` provides a root-only, private, synced phase record for an exact old/new commit, release digest, verified unit-backup manifest digest, grouped-state manifest digest and observed activity of all seven legacy units. Its exclusive transition lock survives interruption and blocks a second writer until recovery has inspected the state. New transactions use journal format v4; v1–v3 were never installed on Beget. This is still a primitive: it does not record marker state or orchestrate the full unit switch and rollback. The installer must recheck activity immediately before ingress closure because services can change after the initial inventory.

`scripts/release/inspect-migration-recovery.mjs` gives a read-only fail-closed classification for an interrupted transition, orphaned marker, missing marker, or incomplete journal. It re-verifies the referenced unit snapshot against its stored digest and never grants permission to open ingress. The installer still needs to verify actual systemd state against the recorded activity before any recovery action.

`scripts/release/stage-pre-exposure-recovery.mjs` now prepares a fully checked grouped restore in a **new** private directory only for `snapshotted`, `switched` or `locally-healthy`. It requires an intact journal-bound unit and state backup, no transition lock, the trusted marker and loaded ingress and writer guards, an absent transient writer permit, all dedicated ingress units inactive, and an explicit exclusive public route proof. For `switched` and `locally-healthy`, the writer check expects the managed binding; an interrupted partial switch requires separate unit repair before staging. It checks those boundaries again after restoring and removes the staged copy if they change. An `ingress-open` journal refuses staging even if the marker was later recreated. This does not stop candidate services or replace live files: a separately journaled controller must repeat the checks, stop writers and safely switch all live state and units before reopening ingress.

`scripts/release/inspect-recovery-destinations.mjs` provides a read-only check after staging: the manifest-bound config and SQLite source paths must be distinct real paths outside the staged copy, the live configuration must have the same entry inventory, types, owners and modes as the verified restore, and each database must have the expected owner and mode. A WAL, SHM or rollback-journal sidecar blocks replacement pending explicit handling. The check returns destination inode identities for a future controller to compare again just before mutation. It does not stop writers, establish exclusive ingress, write data or authorize a rollback; later journaled replacement must address interrupted multi-file commits and possibly changed live state.

`scripts/release/restore-systemd-unit-backup.mjs` restores the original seven unit fragments and any recorded drop-ins into a **new** private directory, requiring the exact journal-bound backup digest. It verifies source bytes, staged bytes, ownership and modes, syncs the staged files and directories, and removes partial output on failure. It does not touch `/etc/systemd/system`, reload systemd or restart services. A future recovery controller must retain the installed ingress and writer guards while any migration marker remains and must journal each live unit mutation before applying staged originals.

`scripts/release/stage-complete-pre-exposure-recovery.mjs` composes the verified grouped state and original unit restores under one new private root for `snapshotted`, `switched` or `locally-healthy`. It verifies the exclusive route, closed ingress, trusted marker, loaded writer and ingress guards, absent writer permit and intact journal-bound backups before and after staging the pair. It also inspects the manifest-bound live destinations against the staged data and returns their inode identities. A changed configuration inventory, database permissions or SQLite sidecar removes the entire staged pair. This staged output is disposable and has no authority to change live state or systemd; a separate crash-recoverable controller must repeat the checks and journal all replacement steps.

`scripts/release/verify-staged-recovery-pair.mjs` reopens a prepared pair without relying on the earlier in-memory result. It compares each staged config, SQLite and original unit file with the journal-bound manifests, rejects added files or changed ownership and modes, rechecks live destination topology and verifies the closed-ingress boundary before and after reading. This read-only check still does not make a multi-file live replacement atomic; its returned inode evidence must be rechecked by the future controller just before writing.

`scripts/release/prepare-pre-exposure-rollback.mjs` writes a root-owned, synced and exclusive `prepared` rollback intent outside the backups and staged pair. It records the exact migration transaction and phase, both backup manifest digests, the staged directory inode and the live destination inode identities obtained by reopening the full recovery pair. A later read-only verifier requires all of these bindings and the closed-ingress boundary to remain valid. This intent does not modify live state or units; a controller still needs a separate crash-recoverable journal for every replacement step and a tested service restart before reopening ingress.

`scripts/release/stop-candidate-for-rollback.mjs` handles the `locally-healthy` candidate under the persistent marker. It verifies the prepared intent, installed guards, absent permit, paused admission and drained local requests, then writes and syncs `stopping` intent before stopping OAuth MCP → base MCP → Agent → Session Host. It checks the terminal ledger before Session Host, preserves `KillMode=process`, and records `stopped` only after all writers are inactive and the recovery bindings still pass. ## Failure and rollback invariants

| Failure point | Safe recovery target |
|---|---|
| Before ingress closure | Leave R0003 running; remove only unused staging. |
| After ingress closure, before switch | Restore stopped R0003 services from unchanged old code roots; keep ingress closed until local health is proven. |
| After switch, before opening ingress | Stop candidate writers; restore the grouped snapshot and original unit/drop-in bindings while closed; restart old services and verify health; only then reopen dedicated ingress. |
| After opening ingress | Automatic state rewind is **not** allowed: new user actions, token revocations or file changes may have happened. Require a compatibility-checked forward repair or an explicitly reviewed rollback plan that preserves those actions and revoked credentials. |
| After power loss | Persistent boot guard keeps OAuth proxy and tunnel closed. Recovery uses the journal and snapshot to decide roll forward or roll back; it must not assume a restarted process is healthy. |

SQLite restore must account for `-wal`/`-shm` sidecars and ownership of each service's state directory. The live replacement executor rejects sidecars and retains a durable ledger across mixed intermediate states; its composed recovery path still needs a full disposable systemd failed-update rehearsal. The unit backup includes the four bridge fragments, OAuth drop-in, proxy socket/service and tunnel fragment in the ingress snapshot slice. It does **not** back up a later boot-guard override. No public update or N/N-1 rollback gate is accepted until guard installation/recovery and a disposable systemd migration/failed-update test pass, followed by exact-commit Beget evidence.
