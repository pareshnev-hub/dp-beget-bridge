# ADR-013 — Real-client acceptance may use an outbound-only test tunnel

Status: Accepted  
Date: 2026-09-22

## Decision
DP-003 real ChatGPT compatibility evidence may be collected through OpenAI Secure MCP Tunnel as a temporary acceptance harness under DP-017.

The tunnel is test-only. The production Direct path remains a stable HTTPS endpoint with local OAuth, consent and revocation as defined by ADR-005 and R0003. Secure MCP Tunnel is not a production transport, public distribution mechanism or mandatory runtime dependency.

The Beget MCP listener remains loopback-only. The tunnel client must use a fail-closed authenticated local hop, a dedicated bounded service identity and a separately protected/revocable Platform runtime key. If the supported tunnel client cannot preserve the existing local authentication boundary, deployment stops instead of adding an unauthenticated listener.

## Reason
DP-003 requires evidence from the actual target client, but the production HTTPS/OAuth path belongs to R0003, which depends on accepted R0002. An outbound-only developer-mode tunnel collects the missing compatibility evidence without exposing the preview bearer, modifying Traefik or prematurely adopting the R0003 production topology.

Official reference: <https://developers.openai.com/api/docs/guides/secure-mcp-tunnels>

## Consequences
- No inbound firewall, DNS, TLS or Traefik change is needed for DP-017.
- Tunnel evidence can close DP-003 compatibility verification but does not satisfy R0003 OAuth/E2E or public-release gates.
- The test depends on current OpenAI Platform tunnel availability, permissions and a user-controlled runtime API key.
- Teardown revokes the key/tunnel association and removes only the tunnel service; the Direct runtime remains healthy and private.
