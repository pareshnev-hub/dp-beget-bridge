# DP Beget Bridge — правила продукта

Обновлено 07.10.2026, Europe/Moscow. Продукт: отдельный Linux VPS MCP bridge; это не Desktop Connector, Yandex Connector или веб-сайт pareshnev.

## Центральный NHN

Источник: Project Source N8N `NHN-AGENT-POLICY-LIVE`; единственный разрешённый fallback — подключённый Google Drive connector для https://drive.google.com/drive/folders/1sX0Fh1qkZO5JRQTQoOKlPp3soc_KWIEh.

Фактически прочитана **NHN 1.7.0**, 07.10.2026: Version → Router → Info, затем модули 00/01/02/03/05/04/06 через точную LIVE-папку подключённого Google Drive. SHA-256 всех девяти прочитанных модулей совпали с Version. Исходная недоступность инструментария снята в этой Work; запись `CENTRAL_POLICY_UNREADABLE_IN_THIS_WORK` в раннем отчёте — историческое состояние. Центральный комплект и `sources/` не редактировать. При старте/восстановлении повторно проверить Version и читать только изменённые нужные модули.

## Обязательные границы

- Direct Mode автономен; центральные сайт, аналитика и Relay не являются зависимостями исполнения.
- Телеметрия по умолчанию выключена. Секреты, production `.env`, OAuth-коды/токены, транскрипты и пользовательские файлы в Git/Drive не сохранять.
- Разделение Session Host / Agent / MCP и OS-пользователей сохранять. Full shell честно раскрывает права ОС; файловый scope не ограничивает произвольную shell-команду.
- Не менять работающий Beget R03, N8N/Traefik, приложения, DNS или синхронизацию Stand без отдельной задачи.
- Ubuntu 24.04/Linux `/proc`, systemd, tmux и ACL проверяются в подходящей среде. macOS не доказывает эти свойства; синтетическое согласие и изолированный Caddy не заменяют реальный клиент/публичную установку.
- Не ослаблять проверки закрытого входящего маршрута, подписи, сетевого пространства, прав, отзывов доступа и восстановления ради прохождения теста.
- Сохранять незапушенную и параллельную работу. Добавочные recovery/handoff-ветки; никаких force push, push --mirror, автоматического merge или удаления исходников.
- Принятые ADR — ограничения архитектуры; фундаментальные изменения требуют отдельного решения. Статус повышать только по точным доказательствам, а не по числу коммитов.
- Писать по-русски; первая строка сообщения `HH:MM DD.MM.YYYY`, затем пустая строка. Использовать актуальную часовую зону клиента.
